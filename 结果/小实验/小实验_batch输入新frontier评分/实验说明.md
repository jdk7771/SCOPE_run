# 小实验：batch 输入新 frontier 评分

对应分支：`feat/batch-frontier-potential-scoring`  
核心代码 ref：`dbbab92`  
性质：frontier potential scoring 调用方式小实验

## 这个小实验做什么

这个小实验只改 frontier potential scoring 的调用方式。

原来的方式是每个新 frontier 单独问一次 VLM：

```text
task + frontier_0 image -> frontier_0 score
task + frontier_1 image -> frontier_1 score
task + frontier_2 image -> frontier_2 score
```

这个分支改成一次请求里输入多个新 frontier，让 VLM 以 JSON 返回多个分数：

```text
task + F_0 image + F_1 image + F_2 image
-> JSON 返回 F_0/F_1/F_2 的 potential scores
```

这里的“batch 输入新 frontier”指的是 potential scoring 阶段的 batch 请求，不是 readable-BEV 主方法本身。

## 为什么做

目的有两个：

- 减少 VLM 请求次数。
- 检查多个 frontier 合成一个 scoring 请求后，解析和 frontier ID 映射是否稳定。

关键实现点是 batch 内部使用局部 `F_0..F_{n-1}`，解析后再映射回 planner 的原始 frontier ID，避免 VLM 返回局部编号时被误解释成全局编号。

## 核心指标

正式对比结论见 `对比结果.md`。这里保留完整小实验指标和历史参考。

| 结果 | 任务数 | Snapshot success | Distance success | Snapshot SPL | Distance SPL | 完成段耗时 | VLM 成功请求 |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| 旧 baseline_ceping split 1 | 278 | **20.50%** | 40.65% | **17.13%** | 29.11% | 15:39:34 | 4,059 |
| 当前 baseline/fix split 1 | 278 | **20.50%** | **44.24%** | 16.29% | **31.66%** | **14:02:41** | 3,461 |

时间上，`batch reason2` 比当前 baseline/fix split 1 的最终完成段多 43 分钟；baseline/fix split 1 的 log 里还有 01:11:34 中断段，若按 log 累计尝试时间算则 baseline/fix 是 15:14:15。VLM 成功请求方面，当前 baseline/fix split 1 是 3,461 次，不是 4,422 次；4,422 是 baseline/fix split 3 的统计。因此不能说 `batch reason2` 比当前 baseline/fix split 1 少 911 次请求。

这个小实验真正能说明的是：修复 batch-local frontier ID 后，`batch reason2` 相比 `batch reason1` 明显更稳定、请求更少；但它相对当前正式 baseline/fix 没有带来导航指标提升，也没有严格证明更省请求。

## batch stage 结果

`vlm_timing.json` 中的 `stage_summary.frontier_potential_batch_step` 更能说明 batch 逻辑是否稳定：

| 结果 | batch stages | 成功 stages | 失败 stages | total frontier items | 成功 stage 平均耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| batch reason1 | 1,285 | 161 | 1,124 | 2,098 | 9.135 s |
| batch reason2 | 618 | 614 | 4 | 983 | 6.683 s |

## 结论

- 第一次 batch 小实验失败 stage 很多，说明 batch 请求、解析或编号映射还不稳定。
- 第二次修复 batch-local frontier ID 后，stage 成功率从 161/1,285 提升到 614/618。
- 第二次 VLM 成功请求数为 3,511，比旧 baseline pilot 的 4,059 更少，也比 `batch reason1` 的 4,841 更少。
- 但导航成功率没有提升：batch reason2 的 Distance success 是 40.65%，低于当前 baseline/fix split 1 的 44.24%。

因此这个分支应作为小实验/效率探索保留，不作为主方法。
