# 对比结果

对比对象：

| 方法 | 分支 | 结果目录 |
| --- | --- | --- |
| 5 cm baseline/fix | `baseline/fix-tsdf05cm` | `01_基线_fix-tsdf05cm/原始结果文件/` |
| metric readable-BEV | `feat/metric-frontier-readable-bev` | `02_可读BEV_metric-frontier-readable-bev/原始结果文件/` |

## 实验目的

这个大实验回答的问题是：

在相同 GOAT-Bench split 1/2/3、相同 5 cm TSDF 条件下，加入 readable structured-BEV、Gaussian evidence BEV、米制 frontier 参数和结构化输出后，是否比非 BEV baseline 更好？

## 方法区别

`baseline/fix-tsdf05cm` 是当前公平 baseline：

- 使用 5 cm TSDF。
- 修复 stale snapshot object ID。
- 记录 VLM timing。
- 不给高层 VLM 额外输入 semantic BEV / Gaussian evidence BEV。

`feat/metric-frontier-readable-bev` 是当前主方法：

- 使用 5 cm TSDF。
- frontier 参数改成米制。
- 给高层 VLM 输入 semantic BEV 和 Gaussian evidence BEV。
- VLM 输出结构化 JSON，再映射回原 SCOPE 执行接口。

## 三 split 合并结果

三 split 合计 810 个 tasks。

| 指标 | baseline/fix 0.05 m | metric readable-BEV | 提升 |
| --- | ---: | ---: | ---: |
| Snapshot success | 18.27% | **26.91%** | **+8.64 pp** |
| Distance success | 39.88% | **48.02%** | **+8.14 pp** |
| Snapshot SPL | 13.84% | **19.39%** | **+5.55 pp** |
| Distance SPL | 27.86% | **32.49%** | **+4.63 pp** |

## 运行时间和 VLM 调用时间

三 split 的 wall-clock 总耗时：

| 方法 | split 1 | split 2 | split 3 | 总耗时 | 平均每 task |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline/fix | 14:02:41 | 13:35:03 | 17:24:40 | 45:02:24 | 200.2 s |
| metric readable-BEV | 20:09:44 | 20:35:10 | 06:29:45 | 47:14:39 | 210.0 s |

readable-BEV 的总耗时比 baseline/fix 多 2:12:15，平均每个 task 多约 9.8 秒。也就是说，主方法带来了明显成功率提升，但运行成本略高。

当前目录中的 `vlm_timing.json` 是可用的 VLM 调用明细文件，metadata 标的是 split 3；它记录的是每次 `chat.completions.create` 的 API 响应时间，不包含本地图像准备、导航执行和 retry sleep。

| 方法 | split | VLM 成功请求 | 平均 API 响应 | 估算 API 响应总时长 | decision 平均响应 |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline/fix | 3 | 4,422 | 6.236 s | 7:39:34 | 11.111 s |
| metric readable-BEV | 3 | 1,599 | 8.478 s | 3:45:56 | 14.728 s |

这个 timing 结果说明：readable-BEV 单次 decision 请求更慢，主要因为输入更复杂；但 split 3 的 VLM 请求次数更少，所以记录到的 API 响应总时长反而更低。最终 wall-clock 仍受本地建图、图像生成、导航执行和场景难度影响，不能只用 VLM API 时间解释总运行时间。

## 结论

`feat/metric-frontier-readable-bev` 在 split 1/2/3 的四项核心指标上都高于 `baseline/fix-tsdf05cm`。合并后 Snapshot success 从 18.27% 到 **26.91%**，Distance success 从 39.88% 到 **48.02%**。

因此，这个分支可以作为当前最重要、验证最充分的主结果。它的代价是 VLM 输入更复杂，整体运行耗时更长。

## 不要过度解释的地方

这个实验验证的是一组改动的总效果，包括米制 frontier、readable BEV、Gaussian evidence BEV 和结构化输出协议。不能单独说提升只来自某一个单独模块。
